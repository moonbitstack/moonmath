approxfunction

pub fn approx(Float, Float, eps? : Float) -> Bool

Whether two numbers are the same to within eps.

Without an epsilon the comparison uses default_epsilon, scaled up for values whose magnitude would swamp an absolute tolerance. Equality itself is exact — == on two numbers that took different paths to the same place rarely holds — so this is the test callers want for results of arithmetic.

mbt check
test {
let a : Float = 0.1 + 0.2
assert_true(@moonmath.approx(a, 0.3))
assert_false(@moonmath.approx(a, 0.31))
assert_true(@moonmath.approx(a, 0.31, eps=0.02))
}

0 and tau are the same direction, and so are -pi and pi; comparing them as plain numbers says otherwise.

default_epsilonvalue

pub let default_epsilon : Float

The absolute tolerance approx falls back on when the caller gives none.

It is a compromise: large enough to cover the rounding of a handful of operations at this precision, small enough that values a user would call different do not compare equal.

inverse_lerpfunction

pub fn inverse_lerp(Float, Float, Float) -> Float

Where value sits between start and end, as a fraction: the inverse of lerp.

Returns zero when the two ends are equal — there is no fraction between them, and zero is the answer that keeps lerp from producing a NaN.

remapfunction

pub fn remap(Float, Float, Float, Float, Float) -> Float

value taken from the range from_start..from_end and placed in to_start..to_end.

It is lerp(to_start, to_end, inverse_lerp(from_start, from_end, value)): the value keeps its position within the range, and values outside the source range land outside the destination range by the same proportion.

smoothstepfunction

pub fn smoothstep(Float, Float, Float) -> Float

A smooth step from zero at start to one at end, zero slope at both ends.

The curve is 3t² - 2t³ over the normalised position, which is the cheapest easing whose first derivative vanishes at both ends — no visible corner where the animation starts or stops.

A zero-width range has no slope to smooth: it steps at start.

wrapfunction

pub fn wrap(Float, Float) -> Float

value folded into 0..span.

Angles and texture coordinates repeat, and a value that has run past the end of its range has to come back to the start rather than stop there. A span of zero or less has nothing to fold into and gives zero.

mbt check
test {
assert_eq(@moonmath.wrap(7.5, 5.0), 2.5)
assert_eq(@moonmath.wrap(-1.0, 5.0), 4.0)
}

wrap_rangefunction

Vec2struct

pub(all) struct Vec2

A point or a direction in the plane.

Two scalars side by side, in the order the plane's axes are named: x runs east, y runs north. Nothing here knows whether +y points up the screen or down it — that is a convention of the canvas, not of the arithmetic.

Values are immutable; every operation returns a new one.

The operators take two vectors of the same type. There is no Vec2 * Float, because a value can only carry one Mul implementation here: scalar scaling is scale, its inverse divide.

Vec3struct

pub(all) struct Vec3

A point or a direction in space.

Right-handed: x and y as in the plane, z towards the viewer in the usual camera setup, so that cross(x, y) == z.

Values are immutable; every operation returns a new one.

The operators take two vectors of the same type. Scalar scaling is scale and divide, not * and /, which belong to the component-wise product.

Quatstruct

pub(all) struct Quat

A rotation, as a unit quaternion.

(x, y, z) is the axis of the rotation scaled by the sine of half its angle, and w the cosine of half the angle. Half angles, because a rotation acts on a vector from both sides: q v q⁻¹.

A quaternion is four numbers where a matrix is nine, composes in fewer operations, and interpolates smoothly — which is why animation and physics carry rotations this way and convert to a matrix only when handing one to a shader.

The rotations are the unit quaternions; the ones here do not enforce that on construction, because building one by summing or lerping intermediate values is legitimate and only the end result has to be normal. Anything that composes an arbitrary number of them — rotate, to_mat3, slerp — says when it assumes unit length.

EulerOrderenum

pub(all) enum EulerOrder

The order the three Euler angles are applied in.

The name says which axis each angle turns about, read left to right: Xyz turns about x, then about the new y, then about the new z. That is the intrinsic reading, the one an aircraft's roll, pitch and yaw use, and it is the same as applying the three turns about the fixed axes in the opposite order.

Six orders turn about three different axes and six about two — the last group repeats the first axis and is what a turntable and a gyroscope do. Between them they cover every way to name a rotation by three angles; the choice is a convention of the file format or the editor that produced the angles, not of the arithmetic.

pub fn Frustum::from_matrix(Mat4) -> Self?

The frustum of a view-projection matrix whose depth range is 0..1, or None when the matrix does not describe one.

The six planes are the six clip-space inequalities pulled back into world space: the left plane is the row w + x of the matrix, and so on. A matrix that is singular or degenerate — a projection with no near plane, say — gives a plane with no normal, and there is no frustum to return.
