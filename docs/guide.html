Eight steps, from a vector to a culled scene

Every listing below is a program that was run to write this page, and every printed line is what it printed. Nothing here is a sketch of an API to come.

§ 1

Getting it, and the first vector

The package is one module with two packages inside: the default single precision one, and moonmath/f64. Adding the module is enough for both.

shell 
moon add moonbitstack/moonmath

A vector is a value: immutable, small, and returned by everything that takes one. The first useful thing to know is the handedness, because it decides a sign you will meet on the first day.

listing 1 · handedness 
let forward = @moonmath.Vec3::new(0.0, 0.0, -1.0)  // where the eye looks
let up = @moonmath.Vec3::unit_y()
let right = forward.cross(up)                       // +x, not -x

println(right)
println(forward.dot(up))
printed
Vec3(1, 0, 0)
0

x runs east, y north and z towards the viewer, so cross(x, y) is z and a camera looking down −z has its right hand along +x. A left-handed system would give the opposite sign here, and a mirrored world at the end of it.

The import name is the last part of the module path: @moonmath, and @f64 for the second precision.

§ 2

Vectors, and what an operator means

The operators work component by component, between two values of the same type. a * b is not a dot product and not a matrix product: it is the product of the components, which is what a shader means by a * b too. The dot product has a name because it is a different thing.

listing 2 · arithmetic 
let a = @moonmath.Vec3::new(1.0, 2.0, 3.0)
let b = @moonmath.Vec3::new(4.0, -5.0, 6.0)

println(a + b)          // component by component
println(a * b)          // the same, multiplied
println(a.dot(b))       // one number
println(a.length())
println(a.normalize())
println(a.lerp(b, 0.25))  // a quarter of the way to b
println(a.min(b))        // component by component, the smaller
printed
Vec3(5, -3, 9)
Vec3(4, -10, 18)
12
3.7416575
Vec3(0.26726124, 0.5345225, 0.8017837)
Vec3(1.75, 0.25, 3.75)
Vec3(1, -5, 3)

The zero vector has no direction, and normalizing it would divide by zero. The library returns the zero vector rather than a NaN, and try_normalize is there for callers who need to know which case they are in.

listing 3 · a direction that isn't one 
let nothing = @moonmath.Vec3::zero()

println(nothing.normalize())       // no NaN escapes
println(nothing.try_normalize())   // the caller can tell
printed
Vec3(0, 0, 0)
None

The scalars beside them

Angles are radians everywhere in the library, and the conversion happens at the edge, where the number came from a file or a person. The easing and wrapping helpers are plain functions, not methods, because they belong to no type in particular.

listing 4 · four useful functions 
println(@moonmath.smoothstep(0.0, 1.0, 0.25))  // 3t² − 2t³ at t = 0.25
println(@moonmath.wrap(7.5, 5.0))              // into 0 … 5
println(@moonmath.to_degrees(@moonmath.half_pi))
printed
0.15625
2.5
90

Two vectors, one operator. MoonBit declares mul(Self, Self), so Vec3 * Float cannot exist. Scaling is scale, and dividing is divide.

normalize keeps the zero vector at zero on purpose: a NaN spreads through a scene graph faster than any warning.

§ 3

Matrices, and the order they multiply in

A matrix is built from its columns, because that is the order it is stored in. Three columns, three vectors, one matrix.

listing 5 · a matrix and its inverse 
let m = @moonmath.Mat3::from_cols(
  @moonmath.Vec3::new(1.0, 2.0, 3.0),
  @moonmath.Vec3::new(4.0, 5.0, 6.0),
  @moonmath.Vec3::new(7.0, 8.0, 10.0),
)

println(m.determinant())
println(m * m.inverse().unwrap())
println((m * m.inverse().unwrap()).approx(@moonmath.Mat3::identity()))
printed
-3
Mat3[Vec3(1, 0, 0), Vec3(0, 1, 0), Vec3(0, 0, 1)]
true

inverse returns an Option, because a matrix can be singular and the caller has to decide what that means. When the case cannot happen, unwrap says so at the point where the knowledge is. The / operator aborts instead, since it has nowhere to report anything.

the order

a * b applies b first. A scene graph reads left to right when you write it — projection, view, model — and each is applied to the result of the one on its right. If the world comes out inside-out, this is the line to check.

A matrix times a vector is not *, because the two sides would have different types. It is a method, and there is one for each size:

listing 6 · three ways to multiply 
let v3 = @moonmath.Vec3::new(1.0, 0.0, 0.0)
println(m.mul_vec3(v3))

let v4 = @moonmath.Vec4::new(1.0, 0.0, 0.0, 1.0)
let big = @moonmath.Mat4::from_mat3(m)
println(big.mul_vec4(v4))
printed
Vec3(1, 2, 3)
Vec4(1, 2, 3, 1)

The determinant of this matrix is −3, so it turns the axes inside out as well as stretching them.

§ 4

A camera, in two matrices

A camera is a view matrix and a projection matrix. The first moves the world so that the eye is at the origin looking down −z; the second squeezes what it sees into the unit cube the clipper expects. Multiplying them gives the matrix a vertex shader takes.

listing 7 · a view, a projection, and a point 
let eye = @moonmath.Vec3::new(0.0, 0.0, 6.0)
let view = @moonmath.Mat4::look_at(
  eye,
  @moonmath.Vec3::zero(),
  @moonmath.Vec3::unit_y(),
)
let projection = @moonmath.Mat4::perspective(
  @moonmath.to_radians(60.0),
  1.5,
  0.1,
  100.0,
)
let view_projection = projection * view

println(view_projection.transform_point(@moonmath.Vec3::zero()))
printed
Vec3(0, 0, 0.9843177)

The origin of the world is dead centre of the screen, so its x and y are zero, and its depth is 0.98 — nearly at the far plane, because the eye is six metres away and the far plane is a hundred. Point the same matrix at the two planes and the convention shows itself:

listing 8 · the two ends of the depth range 
// 0.1 in front of the eye, and 100 in front of the eye.
println(view_projection.transform_point(@moonmath.Vec3::new(0.0, 0.0, 5.9)))
println(view_projection.transform_point(@moonmath.Vec3::new(0.0, 0.0, -94.0)))
printed
Vec3(0, 0, 0)
Vec3(0, 0, 1)

Zero and one, exactly, as WebGPU clips. The _gl variants of the same four projections map the planes to minus one and one instead, for a pipeline that wants that.

Why 0.98 and not 0.5? Depth is not linear in distance. At six metres out of a hundred, most of the range is already spent.

§ 5

Placement, kept apart

A model matrix is a scale, a rotation and a translation, and keeping the three apart is what makes a transform editable. Trs holds them; Mat4::from_trs turns them into the matrix the shader wants; to_trs reads them back.

listing 9 · a local frame, placed 
let placement = @moonmath.Trs::new(
  @moonmath.Vec3::new(0.0, 2.0, 0.0),
  @moonmath.Quat::from_axis_angle(@moonmath.Vec3::unit_y(), @moonmath.half_pi),
  @moonmath.Vec3::splat(0.5),
)
let model = @moonmath.Mat4::from_trs(placement)

// A local +x, halved, turned a quarter turn about y, then lifted two.
println(model.transform_point(@moonmath.Vec3::new(1.0, 0.0, 0.0)))
println(model.transform_vector(@moonmath.Vec3::new(1.0, 0.0, 0.0)))
printed
Vec3(-5.9604645e-8, 2, -0.49999997)
Vec3(-5.9604645e-8, 0, -0.49999997)

The point is lifted by the translation and the direction is not, which is the whole difference between the fourth component being one and zero. The two tiny values are a quarter turn done in single precision: \(\cos 90°\) is not quite zero, and the matrix says so rather than rounding it away.

listing 10 · reading it back 
let back = model.to_trs().unwrap()

println(back.translation)
println(back.scale)
printed
Vec3(0, 2, 0)
Vec3(0.49999997, 0.5, 0.49999997)

Not every matrix can be taken apart this way. A shear leans the three columns towards each other, and no rotation and scale produces that, so to_trs answers None — the same answer a singular matrix gets.

Affine2 and Affine3 are the same idea with the last row assumed: four numbers less to store, and an inverse that is a 3×3 solve rather than a 4×4 one.

§ 6

Rotation, eight numbers instead of sixteen

A quaternion is four numbers that interpolate, and a matrix is what a shader wants. Both directions are here, and a rotation survives the round trip.

listing 11 · a turn, halfway to it, and the matrix 
let turn = @moonmath.Quat::from_axis_angle(
  @moonmath.Vec3::unit_y(),
  @moonmath.quarter_pi,
)
let half_way = @moonmath.Quat::identity().slerp(turn, 0.5)

println(turn.rotate(@moonmath.Vec3::unit_x()))
println(half_way.rotate(@moonmath.Vec3::unit_x()))
println(turn.to_mat3())
println(@moonmath.Quat::from_mat3(turn.to_mat3()).approx(turn))
printed
Vec3(0.7071067, 0, -0.7071068)
Vec3(0.9238795, 0, -0.3826835)
Mat3[Vec3(0.7071067, 0, -0.7071068), Vec3(0, 1, 0), Vec3(0.7071068, 0, 0.7071067)]
true

A quarter turn about y sends +x towards −z, and half of that turn sends it almost nowhere: slerp walks the arc, so the half-way rotation is a rotation by 22.5°, not a linear blend of the four components.

listing 12 · Euler angles, by axis 
let yaw = @moonmath.Quat::from_euler(
  @moonmath.EulerOrder::Zyx,
  @moonmath.Vec3::new(0.0, 0.0, @moonmath.to_radians(90.0)),
)
println(yaw.to_euler(@moonmath.EulerOrder::Zyx))

// An order that turns about x twice needs the turns by place.
let precessing = @moonmath.Quat::from_euler_turns(
  @moonmath.EulerOrder::Xyx,
  @moonmath.Turns::new(0.3, 1.2, -0.4),
)
println(precessing)
printed
Vec3(0, 0, 1.5707965)
Quat(-0.041249573, 0.53040975, 0.19361468, 0.8243042)

The first component of the vector is the turn about x, wherever in the order that turn comes. All twelve orders are in the lexicon, with the angle at which each one stops being able to say what it means.

slerp and nlerp are both here: the first walks the arc at constant speed, the second is cheaper and looks almost the same for small turns.

§ 7

Geometry, and whether two things touch

A ray is a start and a direction. Asking where it meets a box gives a distance along it, or None.

listing 13 · a ray, a room and a ball 
let room = @moonmath.Aabb3::new(
  @moonmath.Vec3::new(-4.0, 0.0, -4.0),
  @moonmath.Vec3::new(4.0, 3.0, 4.0),
)
let down = @moonmath.Ray3::new(
  @moonmath.Vec3::new(0.0, 2.0, 0.0),
  @moonmath.Vec3::new(0.0, -1.0, 0.0),
)
println(down.intersect_aabb(room))   // the floor is two below
println(down.at(2.0))

let ball = @moonmath.Sphere::new(@moonmath.Vec3::zero(), 1.0)
let ahead = @moonmath.Ray3::new(
  @moonmath.Vec3::new(0.0, 0.0, 5.0),
  @moonmath.Vec3::new(0.0, 0.0, -1.0),
)
println(ahead.intersect_sphere(ball))
printed
Some(2)
Vec3(0, 0, 0)
Some(4)

The last piece a renderer needs is the cheapest: throw away what the camera cannot see before drawing it. A frustum built from the same view-projection matrix answers for a box in one call per plane.

listing 14 · culling 
let frustum = @moonmath.Frustum::from_matrix(view_projection).unwrap()
println(frustum.intersects_aabb(room))       // in front of the camera

let far_room = @moonmath.Aabb3::new(
  @moonmath.Vec3::splat(50.0),
  @moonmath.Vec3::splat(60.0),
)
println(frustum.intersects_aabb(far_room))   // behind it
printed
true
false

The frustum test is conservative on purpose: a box that straddles the edge of the screen is kept, because dropping something visible is worse than drawing something invisible.

§ 8

The same library, in double

Import moonbitstack/moonmath/f64 and every type appears again with Double where Float was. The names, the operators and the documentation are the same; only the numbers change.

listing 15 · a millimetre, at a billion metres 
let far = @f64.Vec3::new(1.0e9, 0.0, 0.0)
let step = @f64.Vec3::new(1.0e-3, 0.0, 0.0)
println(far + step)

let near = @moonmath.Vec3::new(1.0e9, 0.0, 0.0)
let small = @moonmath.Vec3::new(1.0e-3, 0.0, 0.0)
println(near + small)
printed
Vec3(1000000000.001, 0, 0)
Vec3(1000000000, 0, 0)

At a billion, single precision counts in steps of sixty-four, so a millimetre is not a small distance — it is no distance at all. A simulation that spans a solar system wants the second package; what it sends to the GPU still wants the first.
